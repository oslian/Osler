# Same Query, Matched Size: Seen Versus Unseen Component

Freeze the prior Huber correction and all its settings. For each of five
calibration roles, choose20%of people within each component by fixed SHA256
priority, before target availability/outcomes. These are query patients for
alltargets; no patient's other targets enter correction fitting.

For each target/query component, unseen fit uses all non-query people outside
that component. Seen fit samples the same number from all non-query people by
a second fixed hash priority. Require actual same-component exposure in seen
fit and zero query overlap in BOTH. Record input support and nonconvergence.
No feature/penalty tuning. Both process-context and numeric-context corrected
forecasts refer to the same frozen current-value reconstruction base.

Score EXACTLY the same query rows for both fits. Use per-component MAE and
equal-component means versus unchanged, plus matched unseen-minus-seen error.
Only fully supported/converged pairs are scored; incompleteness is explicit.
Summaries require all queried components successfully fit and>=3query
components with>=30people, not selected favorable groups. Full low-count
component rows remain reported. No claim that matched N equalizes case-mix,
training component count, weights or variable support; these are part of the
domain-exposure contrast. One fixed hash split, not a new seven-seed gate.

No outer evaluation/promotion. Improvement seen but not unseen would support
domain exposure sensitivity; harm in both would refute a purely unseen-domain
explanation. Neither alone proves a unique clinical or encoder cause.
